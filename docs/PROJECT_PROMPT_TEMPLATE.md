# 관제 대시보드 — 프로젝트 제출 프롬프트 (고정 양식)

새 프로젝트에서 관제 대시보드를 띄우려면 **이 양식을 채워 프롬프트로 제출**한다.
선언 파일이나 어댑터 코드를 따로 쓰지 않는다 — 세션에서 정리한 내용이 그대로 입력이다.

> **쓰는 법**: 아래 9절을 채운다. 모르는 항목은 `(미상)`으로 두되 **비워 두지 말 것** —
> 빈칸과 "없음"은 다르고, 대시보드는 그 차이로 패널을 넣을지 뺄지 정한다.
> 채운 뒤 `~/robot-dashboard`에서 `/dashboard-gen <이 파일 경로>` 로 실행한다.


**캡스톤 예시**
> 이 프로젝트는 **모바일 매니퓰레이터(SO-101 + 차동구동)로 색 큐브를 집어 통에 넣는 것**을 하는
> **ROS 2 Jazzy + Gazebo Harmonic 시뮬 캡스톤**이다.
> 관제의 목적은 **디버깅**이다 — 어느 단계에서 왜 실패하는지 좌표와 신호로 짚는 것.

## 4. 시퀀스 정의 (⑤ SFC 그래프·타임라인이 쓴다)

작업을 **단계 그래프**로 적는다. 각 단계에 진입/이탈 조건을 붙인다.

```
캡스톤 예시 (팔 단독 모드)

무대배치 ──▶ 손목캠정렬 ──▶ 하강 ──▶ 삽입 ──▶ 닫기 ──▶ 들기 ──▶ 선회 ──▶ 하강 ──▶ 개방
   │            │  서보 오차      │ 큐브 밖      │ 물림각      │ 4계단     │ pan 회전
   │            │  <3mm 수렴      │ APPROACH_BACK│ >0.15      │ up 0.02~  │ 높이 유지
   │            └─ 기울기 측정 ───┘              └ effort<−1  └ 0.18      └ 그다음 하강
   └ 배치 확인 (gz model -p, 재시도 3회)
```

| 단계 | 진입 조건 | 성공 조건 | 실패 신호 |
|---|---|---|---|
| 손목캠 정렬 | 팔이 프리그래스프 | blob 오차 <3mm | 미검출 → 좌우 훑기 |
| 닫기 | 삽입 완료 | 물림각 >0.15 AND `\|effort\|`>1.0 | 각도 −0.17 = 허공 |
| 들기 | 물림 확인 | 큐브 z 상승 >10mm | 물림각 단조 감소 = 짜냄 |
| 투입 | 통 위 도달 | 실좌표 통 중심 <68mm | — |

**디지털 신호 라인** (botrail 타임라인 하단처럼 겹쳐 그릴 것)
> `gripped` · `part_at_pick` · `spec_ok` · `busy` 같은 불리언을 시간축에 띠로.
> 캡스톤 대응: `_ik_grasped` · `_carrying` · `_trash_from_marker` · `_carry_drop`

## 5. 판정 기준 (대시보드가 성공/실패를 색칠하는 근거)

> **로그를 믿지 말 것.** 이 프로젝트는 `PICK_SUCCESS`가 찍혔는데 실좌표로는
> 통에서 397mm 벗어난 사례가 있다. 판정은 반드시 **물리적 결과**로 한다.

| 판정 | 기준 | 근거 |
|---|---|---|
| 최종 성공 | 큐브가 통 개구부 안(반폭 68mm) AND z < 0.090 | `gz model -m <name> -p` 실좌표 |
| 파지 성공 | 물림각 >0.15, `effort` <−1.0 | 허공은 각도 −0.17, effort 0 |
| 들기 성공 | 큐브 z 상승 >10mm | 로그가 아니라 좌표 |
| 측정 유효 | **RTF ≥ 0.9** | 미만이면 결과 폐기 |

## 부록 A. 이 양식이 만들어 내는 것

채워 제출하면 대시보드는 다음을 자동 구성한다.

| 제출 항목 | 생성되는 화면 |
|---|---|
| 2절 관절표 + URDF | 3D 뷰 · 관절 트리 · 슬라이더(한계 반영) |
| 3절 신호 목록 | 시계열 차트 · 게이지 · 경보 배지 (없는 신호는 **숨김**) |
| 3-3 카메라 | 영상 패널 (단계별 유효 카메라 표시) |
| 4절 시퀀스 | SFC 그래프 · 스텝 목록 · 타임라인 신호 띠 |
| 5절 판정 | 성공/실패 색칠 · 실좌표 대조 배지 |
| 6절 기록 | 타임라인 스크럽 · 재생 컨트롤 |
| 7절 병목 | 첫 화면 상단 "지금 여기가 막혀 있다" 카드 |

## 부록 B. 채울 때 흔한 실수

- **단위를 안 적는다** — `effort`가 N·m인지 정규화값인지 모르면 경보선을 못 긋는다
- **"없음"과 빈칸을 섞는다** — 없으면 "없음", 모르면 `(미상)`
- **로그 기준으로 성공을 정의한다** — 물리적 결과로 적을 것
- **함정을 안 적는다** — RTF·프로세스 정리·퍼블리셔 이중화 같은 것이 가장 값지다
