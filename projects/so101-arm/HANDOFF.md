## 1. 하드웨어 사고 — 원인 확정

**`wrist_roll`(ID 5) 서보가 과열·발연해 교체했다.** (초기에 `wrist_flex`로 적었던 것은
오판이다 — ID 5만 빼자 나머지 다섯이 살아나 원인이 특정됐다.) 원인은 세 겹이고
전부 코드 쪽 설계 공백이다.

### ① 눌린 죠에 회전을 요구했다 (순서 문제)

`wrist_roll`이 97.98°(누운 자세)라 죠가 좌우로 벌어진 채 팔이 내려가 **한쪽 턱이
책상에 닿았고**, 그 상태에서 IK가 roll을 180°로 돌리라고 명령했다. 눌린 죠는 돌 수
없다 — 82°를 남기고 스톨.

`floor_z_m`(-0.1037)은 특정 roll에서 잰 값인데 "roll이 어떻든 여유가 있다"고
가정한 것이 화근이었다. roll이 90° 누우면 죠 기하가 달라져 닿는 높이가 바뀌고,
죠에 물체까지 물려 있었다.

### ② 보간 루프가 서보 자체 보호를 무력화했다

STS3215 데이터시트 7-11 Electronic Protection:

> **Overload**: 스톨 토크의 80%를 2초 초과하면 보호 진입. **위치 명령을 다시 보내면
> 보호 플래그가 해제된다.**
> **Over Current**: 동작 전류가 2A를 2초 초과하면 출력을 끄고 보호 진입.
> **위치 명령 재전송으로 플래그가 해제된다.**

`_do_move_q`는 **20ms마다 `Goal_Position`을 쓴다.** 서보가 2초를 견디고 스스로
출력을 껐는데 초당 50번 "다시 가라"고 명령해 보호를 계속 풀었다. 막힌 상황에서
`_do_stop()`처럼 현재 위치를 다시 쓰는 것조차 같은 해제 효과를 낸다.

### ③ 도달 실패를 감지하고도 힘을 빼지 않았다

정합 스크립트가 13개 지점 이동을 걸었고 전부 도달에 실패했는데, "건너뜀"만 출력하고
정지 명령을 보내지 않았다. 서보 목표가 그대로 남아 계속 밀었다. 그 상태가 장시간
유지됐고, 발견 시점에는 통신이 끊겨 소프트웨어로 토크도 못 껐다(전원 차단으로 정지).

**교훈**: 실패를 기록하는 것과 안전한 상태로 되돌리는 것은 다른 일이다.

## 2. 안전장치 (6종) — 실물 검증 미완

방어 순서대로:

| # | 장치 | 시점 | 위치 |
|---|---|---|---|
| 0 | **캘리브 범위 검사** | 명령 전 | `arm_gui._clamp_to_calib` |
| 1 | **회전 우선 분할** | 명령 시 | `arm_gui._do_move_q` |
| 2 | 서보 펌웨어 보호 | 즉시 | 연결 시 EEPROM 기록 |
| 3 | 전류 감시 | 0.2초 | `arm_gui._interp` |
| 4 | 스톨 감지 | 0.5초 | `arm_gui._interp` |
| 5 | 과온 감시 | 6초 | `arm_gui._guard` |

**0번이 가장 중요하다.** IK는 URDF 관절 한계로 해를 내는데 그 값이 서보 실측 범위보다
넓다(재캘리브 후 실측):

```
shoulder_pan   서보 ±98.9    URDF ±110.0   → 양끝 11.1° 초과
elbow_flex     서보 ±97.6    URDF  ±96.8   → 초과 없음 (0.8° 여유)
```

**✎ 2026-08-19 저녁 정정**: 종전 표기(-88.4~109.3 / -107.8~87.4)는 중립 2048 고정으로
잘못 환산한 숫자였다. lerobot DEGREES 정규화는 **범위 중점 기준·360/4095** 라 서보
한계는 항상 ±대칭이다 — 경계 환산은 반드시 `arm_lib.calib_bounds()` 하나만 쓸 것.
(잘못된 식은 shoulder_pan 에서 12.5° 오차단·8.4° 과허용을 만들고 있었다.)

범위 밖을 명령하면 서보는 갈 수 있는 데까지 가서 **나머지를 계속 민다** — 사고와
같은 구조다. 이제 이동을 시작조차 하지 않는다(양 끝 2° 여유).

**1번**: `wrist_roll` 변화가 20°를 넘으면 나머지를 그대로 둔 채 **roll만 먼저** 돌리고
본 이동을 한다. 회전이 막히면 본 이동을 아예 하지 않는다.

### 2026-08-19 저녁 추가분 (가짜 서보 테스트 통과, 실물 미검증)

- **토크 켜기 검사** (`_do_torque`): 켜기 전에 목표를 현재 위치로 덮고, 현재 자세가
  캘리브 범위를 크게 벗어났으면(바깥 3° 허용) 거부한다. "토크를 켜는 것 자체가 위험
  동작" 교훈의 코드화. **검사·기록은 raw 카운트로 한다** — 정규화 읽기는 그리퍼에서
  범위 밖을 0/100 으로 클램프해 버려 범위 밖을 볼 수 없고, 그 값을 되쓰면 켜는 순간
  스스로 움직인다. 인가 루프 실패 시 전체를 도로 내린다. `_do_grip_test` 도 동일 +
  그리퍼 통전 시 `state['torque']` 를 세워 `_guard` 감시가 붙게 했다(종전엔 파지
  유지 중 무감시 통전).
- **조그·그리퍼 범위 검사**: `_do_jog` 가 캘리브 범위를 검사한다(종전엔 goto·move_q만).
  그리퍼는 jog/goto/grip_test/stop_test 전부 0~100 으로 묶었다. `stop_test` 도 같은
  게이트 + 대기 상한 3초 + 0.1초 슬라이스로 abort·과전류 확인(종전엔 검사·상한·중단
  전부 없어 사고 조건을 재현할 수 있었다).
- **fail-closed**: `_clamp_to_calib` 는 캘리브 파일을 못 읽으면 거부한다(종전엔 통과).
  이동 중 읽기 실패는 `_do_stop`(위치 재전송 = 보호 해제) 대신 `_kill_torque` 로 끊는다.
- **스톨 감지를 관절별로** (`_interp`): 종전엔 전체 max 기준이라 **한 관절만 막히고
  나머지가 움직이면 감지 못 했다 — 사고가 정확히 그 모양**(wrist_roll만 막힘)이었다.
  이제 관절별로 "0.5초간 안 움직였는데 보간 목표가 3° 이상 앞서 있으면" 즉시
  `_kill_torque`. 비교 기준을 최종 목표가 아닌 현재 보간 목표로 바꿔 초반 오탐도 없앴다.
  **기는 스톨**(마찰로 1°/s 씩 밀리는 부분 스톨)도 뒤처짐 15° 에서 끊되, 속도 상한이
  허용하는 만큼 움직이고 있는 관절(정상 저속 이동)은 면제한다.
  가짜 버스 재현: 사고 시나리오 1초 내 감지, 정상 이동 오탐 없음.
- **무효 상수 가드** (`arm_lib.load_gain`): `servo_gain.json` 의 `stale_*` 목록에 있는
  키를 요구하면 실행을 멈춘다. `pick_red.py`(floor·y_to_px·기준선)·`align_y.py`(y_to_px)
  가 이걸로 로드해 **재측정 전에는 돌지 않는다**. `floor_z_m`·`cam_up_roll_deg` 를
  `stale_after_recalib` 로 표시했다.
- **handeye 프리플라이트**: 이동 시작 전에 13점 전부를 IK+캘리브 범위로 정적 검증하고,
  floor_z_m 이 stale 이면 거부한다(`--force-floor` 로만 강행).

리뷰(2패스, APPROVE) 잔여 Minor 5건 — 안전 영향 없음, 다음 사이클:
- `state['torque']` 가 "그리퍼만 통전"과 "팔 전체 통전"을 구분 못 한다 → grip_test 직후
  IK 이동이 게이트를 통과하고 팔이 안 움직여 "⛔ 스톨"로 끝난다(움직임 없음·토크 차단이라
  안전한 방향). **grip_test 직후 뜨는 스톨 메시지는 간섭이 아니라 팔 토크 미인가일 수
  있다.** 플래그 분리(`gripper_torque`)가 정석.
- `_do_neutral` 이 `_calib_cache` 를 안 비운다 (호밍이 raw 프레임을 옮긴다) — 한 줄 추가.
- `_do_stop_test` 의 abort 분기가 try 밖 / 전류 읽기 실패 시 `c=0` 으로 감시가 조용히
  꺼진다(3초 상한이라 노출 제한적).
- `calib_bounds` 가 관절 누락 캘리브에서 KeyError 트레이스백(이동 전이라 fail-closed).
- 실물 첫 주행 때: 스톨 로그에 `moved/win_cap` 비율을 남기면 기는-스톨 면제의 오탐
  여부를 로그만으로 판별할 수 있다.

**스톨·과전류 정지는 `_kill_torque()`를 쓴다** — 위치 명령을 보내지 않고 토크를
끊는다. 위치 명령은 서보 보호를 해제시키므로 `_do_stop()`을 쓰면 안 된다.

### 임계값 (`arm_gui.py` 상단)

```
TEMP_WARN, TEMP_STOP = 55, 62      # °C (STS3215 기본 한계 70)
CURRENT_STOP = 250                 # ~1.6A — 12V 정격 900mA 의 1.8배
CURRENT_HOLD = 2                   # 연속 관측 횟수
STALL_GAP_DEG = 3.0
STALL_MOVE_DEG = 0.4
ROLL_FIRST_DEG = 20
LIMIT_MARGIN_DEG = 2.0
```

**★ `CURRENT_STOP`은 아직 추정치다.** 데이터시트(12V 30kg: 무부하 180mA · 정격
900mA · 스톨 2.7A) 기반이고 **실측하지 않았다.** 너무 낮으면 정상 동작에서 오정지하고,
너무 높으면 보호가 안 된다. 이동 로그의 `전류피크` 값을 몇 번 모아 조정할 것.

**정지 상태에서는 전류가 0이다**(감속비 1/345라 중력을 기어가 버틴다). 기준선은
반드시 움직이는 중에 재야 한다. `_guard`(6초 주기)로는 짧은 이동의 피크를 놓치므로
`_interp`가 기록하는 `state['last_peak']`를 봐야 한다.

### 서보 보호 파라미터 (연결 시 자동 기록)

```
표준(ID 1~5): 과온 65도 · Protection_Current 320(~2.1A) · Overload_Torque 60%
              · Protection_Time 0.5초 · Protective_Torque 20%
그리퍼(ID 6): 과온 65도 · Protection_Time 0.5초 · Overload_Torque 25%
              · Protection_Current 250
```

그리퍼를 낮게 잡는 이유: **물체를 잡고 계속 힘을 주는 것이 정상 동작**이라 임계를
다른 관절처럼 올리면 물체를 부수거나 서보가 무리한다. 이 팔의 원래 그리퍼가 25%로
출하됐고 그 의도를 존중했다.

## 3. 캘리브레이션 (2026-08-19 재실시)

`wrist_roll`(ID 5)·`gripper`(ID 6) 교체 후 전 관절 재실시. **중립 자세는 아랫턱
우측 · 캠 위** — 아랫턱이 아래를 향하는 자세는 가동범위에 걸려 만들 수 없다.
손목캠이 그리퍼 **옆면**에 달려 있어 아랫턱이 아래면 캠이 우측을 본다.

```
관절            homing   range        (raw, 중립 2048)
shoulder_pan      1847   1042~3292
shoulder_lift    -1224    765~3328
elbow_flex        1675    822~3042
wrist_flex          21    896~3192
wrist_roll        -945     14~4018    (거의 360도 전체)
gripper            836   2026~3945
```

파일: `~/.cache/huggingface/lerobot/calibration/robots/so_follower/follower.json`
(캐시 경로라 유실 위험 → 사본이 `tools/calibration_follower.json`에 커밋돼 있다)
이전 값 백업: `~/so101_tools/calib_backup_*.json`

**★ `mapping.json`의 `offsets.wrist_roll`을 -180 → 0으로 되돌렸다.** 어제 -180을
넣은 이유는 "서보 중립이 캠-아래 자세로 잡혀 있어서"였는데 재캘리브로 원인이
사라졌다. 오프셋을 남기면 IK 목표가 **항상 ±180 경계**에 놓여, 0.26도 차이를 359.74도
역회전으로 수행하는 문제가 상시화된다(사고의 한 축).
검증: IK(x=0.20, y=0, z=0.02) → `wrist_roll` 목표 `0.00`.

**✎ 캘리브가 바뀌었으므로 `servo_gain.json`의 `floor_z_m`(-0.1037)도 무효다.**
FK 좌표계 기준이 달라졌다. 책상 높이를 다시 재기 전에는 낮은 z 목표를 주지 말 것.

## 4. 서보 교체 절차 (도구 있음)

새 서보는 **팔에 조립하기 전에 단독으로 물려 ID를 먼저 바꾼다.** 공장 기본 ID가 1이라
그대로 꽂으면 기존 `shoulder_pan`과 충돌해 **버스 전체가 먹통**이 된다.

```
python3 ~/so101_tools/servo_check.py                 # 읽기 전용 진단
python3 ~/so101_tools/servo_id.py --to 5             # ID 부여 + 보호 파라미터
python3 ~/so101_tools/servo_id.py --protect-only 6   # ID 변경 없이 보호만
```

`servo_id.py`는 버스에 서보가 **정확히 하나**일 때만 진행한다(둘 이상이면 중단).
`servo_check.py`는 위치 제한이 공장값(`0~4095`)이면 새 서보로 판정한다.

**단락 진단**: 서보 하나가 내부 단락되면 데이지체인 전원 라인을 끌어내려 **전 서보가
무응답**이 된다. 어댑터 LED가 깜빡이면 그 신호다. 서보를 하나씩 물려 가며 좁힌다.

**✎ 판매자가 ID와 위치 제한을 미리 설정해 보내기도 한다.** 이번 교체품은 ID 3·5·6으로
왔고 위치 제한도 들어 있었다. `servo_check.py`로 먼저 확인할 것.

## 5. 뎁스캠 — 해결됨

**원인은 스트림 코드가 아니라 SDK 교착이었다.** Legacy Astra SDK는 같은 USB2 버스의
UVC 캠이 열리는 순간 `astra_update()` 안에서 **영구 교착**한다. 교착 후에도 HTTP
핸들러는 살아 있어 **캐시된 마지막 JPEG를 계속 보내므로** "브라우저에서만 멈춤"으로
보인다. `/depth`만 단독으로 읽으면 정상인데, 그때는 `/cam`이 안 열려 교착이 없기
때문이다.

`depth_daemon.py`가 캡처를 독립 프로세스로 돌린다:

```
GET /all    → {seq, beat_age, stats, blob, depth_jpeg, rgb_jpeg}
GET /health → {seq, beat_age}
```

`beat_age`가 큰 것은 "SDK 안에서 멈춤"만을 뜻한다 — 교착을 정확히 판정하는 계기다.
`panel_server`의 감독 스레드가 하트비트가 끊기면 데몬만 갈아끼운다.

**뎁스캠 전용 빨강 HSV**(손목캠 값을 그대로 쓰면 검출 0):
`[((0,140,55),(10,255,255)), ((166,140,55),(179,255,255))]`
같은 장면 실측 — 물체 `H 168~175 · S 중앙 211 · V 중앙 87`, 사람 팔 `H 5~6 · S 117`.
`V` 하한 100이 물체를 통째로 잘랐고, `S>=140`이면 살색이 전부 빠진다.

**깊이 창 확장**: 구조광이라 물체 주변에 그림자가 생겨 작은 큐브가 통째로 들어간다.
고정 11x11에서는 유효 화소 0 → `cam_xyz=None`. `r = 5 → 9 → 14 → 20`으로 넓힌다.

## 6. 정합(hand-eye) — 미완료

**목표**: `p_rob = R · p_cam + t`. 죠에 물린 빨간 물체로 대응쌍을 모아 Kabsch(SVD)로
푼다. 물체가 죠에서 차지하는 상대 위치는 상수라 `t`에 흡수되므로, 결과는 곧
"카메라가 본 물체 → 그것을 물 TCP 목표"가 된다.

**세 번 실패했고 원인은 전부 도달 판정이었다**(`ce1e4d0`에 수정 반영, **미검증**):

1. IK 목표를 로봇 좌표로 썼다 → 실제 관절값을 읽어 FK로 구하도록 수정
2. "관절 변화가 멈추면 도착"으로 판정 → 명령 직후엔 출발 전이라 변화가 0이다.
   **목표 관절각과의 거리**로 판정하도록 수정
3. 각도 래핑 누락 → `wrist_roll` 목표 -180과 실제 +180이 278도 차이로 읽혔다.
   `(a-b+180)%360-180`으로 정규화

### 재개 절차

1. 빨간 물체를 죠에 물린다. **물렸는지 반드시 확인** — `shoulder_pan`을 ±6도 움직여
   `/blob`의 `cam_xyz`가 따라 움직이면 물린 것, 제자리면 떨어진 것
2. `python3 ~/so101_tools/handeye.py` — 13개 지점 자동 순회
3. 결과 `~/so101_tools/handeye.json`. **RMS 잔차와 점 분포 특이값을 볼 것.**
   최소 특이값 0.02 미만이면 평면 퇴화라 회전이 안 정해진다
4. **팔이 움직이는 동안 자리를 뜨지 말 것**

**✎ 지점 좌표(`POSES`) 도달성은 2026-08-19 저녁 정적으로 재검증했다** — 신규 캘리브
범위 기준 13점 전부 IK 해 있음·범위 안(wrist_roll 목표 0.0). `handeye.py` 가 시작 전에
같은 검증(프리플라이트)을 스스로 돌린다. **남은 위험은 아래층 `z=-0.05` 하나다** —
"책상에서 5cm 여유"의 근거인 `floor_z_m`이 무효라, floor 재측정 전에는 스크립트가
스스로 거부한다(`--force-floor` 로만 강행).

## 8. 반복해서 발목을 잡은 것들

- **`systemd-run --user --scope`로 띄운 프로세스는 `kill`로 안 죽는다.** `pgrep -f`가
  잡는 건 래퍼 bash다. 죽인 줄 알았던 서버가 한 시간 넘게 살아 카메라를 물고 있었다.
  `systemctl --user list-units --type=scope | grep <명령>` → `stop`, 포트가 비었는지로
  교차 확인할 것.

- **USB 리셋 ioctl(`USBDEVFS_RESET`)을 원인 좁히기 전에 걸지 말 것.** 장치가 열거조차
  못 하는 상태(`error -71`)로 굳어, 드라이버 unbind/bind · authorized 토글 · 포트
  VBUS 차단 40초 · xhci 컨트롤러 전체 리셋 어느 것으로도 복구되지 않았다.

- **정적 장면에서는 깊이 프레임이 바이트 단위로 동일하다**(mm 양자화). 카메라가 11fps로
  멀쩡히 돌아도 화면은 정지와 구분되지 않는다. → 깊이 화면 좌상단에 시각·fps를 그렸다.

- **`/tmp` 백업으로 롤백하지 말 것.** 임시 실험 전 백업이 오래된 버전이어서, 되돌리며
  깊이 창 확장·shutdown join·fps 오버레이가 통째로 유실된 채 커밋됐다.

- **다른 세션이 같은 파일을 편집 중일 수 있다.** `panel_server.py`를 커밋하려다
  다른 세션의 `depth_daemon` 작업을 덮을 뻔했다. `git diff --cached`로 내 변경만
  올라갔는지 확인할 것.

- **토크를 켜는 것 자체가 위험 동작이다.** 부하 측정을 "읽기 작업"으로 취급해 토크를
  켰다가 그리퍼가 범위 밖(위치 제한 이탈)이라 스스로 움직여 기구가 물렸다.
  켜기 전에 **목표를 현재 위치로 먼저 쓰고**, 범위 안인지 확인할 것.

## 9. 파일 위치

**실행 경로는 `~/so101_tools/`다.** 리포의 `projects/so101-arm/tools/`는 **사본**이고,
`panel_server.py`가 `sys.path`에 `~/so101_tools`를 넣어 그쪽을 import한다.
수정 후 반드시 복사할 것.

| 파일 | 역할 |
|---|---|
| `panel_server.py` (리포) | HTTP 서버. `/state` `/cmd` `/cam` `/depth` `/rgb` `/blob`. 깊이 데몬 감독 |
| `depth_daemon.py` (리포) | 깊이 캡처 전용 프로세스 (포트 8766). SDK 교착 격리 |
| `~/so101_tools/arm_gui.py` | 시리얼 워커. 토크·조그·IK 이동·정지·**안전장치 6종** |
| `~/so101_tools/arm_lib.py` | 매핑·운동학 로드, 관절각 <-> 서보각 변환 |
| `~/so101_tools/astra.py` | Astra ctypes 바인딩 |
| `~/so101_tools/handeye.py` | 정합 스크립트 (미검증) |
| `~/so101_tools/servo_check.py` | 서보 진단 (읽기 전용) |
| `~/so101_tools/servo_id.py` | 교체 서보 ID 부여 + 보호 설정 |
| `~/so101_tools/mapping.json` | 부호·오프셋·홈 자세 |
| `~/so101_tools/servo_gain.json` | 실측 상수 (상당수 무효 — 7절 참조) |

**서버 기동**:

```
systemd-run --user --scope -q -p MemoryMax=1G bash -c \
  'export PYTHONPATH=; export LD_LIBRARY_PATH=$HOME/AstraSDK/lib:$LD_LIBRARY_PATH; \
   cd ~/robot-dashboard/projects/so101-arm && exec ~/miniforge3/envs/lerobot/bin/python -u panel_server.py'
```

`panel_server`가 `depth_daemon.py`를 자동으로 띄우고 감독한다.

기동 후 `{"op":"connect"}` → 속도 낮추고 → `{"op":"torque","on":true}` → 즉시 `{"op":"stop"}`.
연결 시 `disable_torque()`가 불려 팔이 처지므로 미리 낮은 자세로 두고, 토크를 켤 때
이전 목표로 튀는 것을 `stop`으로 막는다.
