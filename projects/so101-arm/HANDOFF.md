# SO-101 + Astra 정합 작업 인수인계 (2026-08-19)

## 0. 먼저 — 하드웨어 사고가 있었다

**`wrist_flex`(ID 4) 서보에서 연기와 탄 냄새가 났다. 전원은 차단된 상태다.**

경위:

1. `handeye.py`(정합 스크립트)가 13개 지점으로 IK 이동을 명령했다.
2. 13개 **전부** 목표 도달에 실패했다(스크립트가 "건너뜀"으로 출력).
3. 실패해도 **서보 목표는 그대로 남았다.** 팔은 `wrist_flex 67.56°`에 멈춰 있었고
   마지막 목표는 약 `93°`였다. 25° 못 간 채로 서보가 계속 밀었다.
4. 막힌 이유는 `wrist_roll`이 `97.98°`(캠이 옆으로 누움)였기 때문으로 보인다.
   캠-위 기준은 `-180°`다. 옆으로 누운 상태에서 손목을 꺾으면 손목캠이 팔·책상에
   부딪힌다(사용자가 전날 "팔을 접으면 카메라가 망가질 상황"이라고 지적한 간섭).
5. 스톨 상태가 강의 시간 내내 유지되며 과열됐다. 발견 시점에는 이미 서보와
   통신이 끊겨(`Failed to sync read 'Present_Position' on ids=[1..6]`) 소프트웨어로
   토크를 끌 수 없었고, 전원을 물리적으로 뽑아 정지시켰다.

**직접 원인은 코드가 아니라 설계 공백이다.** 도달 실패를 13번 감지하고도 정지
명령을 보내지 않았다. 실패를 로그로만 남기고 힘은 계속 걸어 두었다. 스톨·부하·
온도 어느 것도 감시하지 않았다.

### 전원을 다시 넣기 전에

1. `wrist_flex` 서보 케이스 변형·탄 자국 육안 확인.
2. 전원 인가 후 **토크를 켜지 말고** 통신만 확인. STS3215는 `Present_Temperature`
   레지스터가 있으므로 ID별 온도를 읽어 손상 판정.
3. ID 4가 응답하지 않거나 온도가 비정상이면 교체 검토.

### 안전장치 (커밋 `622914e` + `79e1645`)

| 장치 | 위치 | 동작 |
|---|---|---|
| **이동 중 스톨 감지** | `arm_gui._do_move_q` | 보간 중 0.5초마다 위치 확인. 0.4° 미만으로 움직이는데 목표가 3° 넘게 남으면 즉시 `_do_stop()` |
| 도달 검증 | `arm_gui._do_move_q` | 보간 후 목표와 3° 넘게 벌어지면 `_do_stop()`으로 미는 힘 제거 |
| 과열 감시 | `arm_gui._guard` | 폴링 25회(≈6초)마다 전 서보 온도 확인, 62°C 이상이면 자동 토크 해제 (55°C 경고) |
| 통신 두절 | `arm_gui._poll` | 읽기 실패가 이어지면 재연결 **전에** `disable_torque` 시도 |
| 정합 실패 | `handeye.py` | 도달·관측 실패 시 `stop` 전송, 연속 3회면 중단, 정상 종료 시에도 `stop` |

임계 상수는 `arm_gui.py` 상단: `TEMP_WARN=55`, `TEMP_STOP=62`, `TEMP_EVERY=25`,
`STALL_GAP_DEG=3.0`, `STALL_MOVE_DEG=0.4`. STS3215 기본 과온 한계가 70°C이므로
그보다 낮게 잡았다.

✎ **첫 구현(622914e)에는 결함이 있었다.** 이동 중에는 `_poll`이 돌지 않아 감시가
통째로 꺼져 있었고 — 서보가 타는 것은 정확히 그 구간이다 — 온도 읽기 실패가
통신 두절로 오인돼 엉뚱한 재연결을 돌렸다. `79e1645`에서 고쳤다.

**검증**: 가짜 서보 버스로 판정 로직을 확인했다(실물은 사고로 사용 불가).
막힌 채 이동 → 스톨 감지 후 `Goal_Position`을 현재 위치로 재기록 / 70°C →
`disable_torque` / 30°C → 무동작 / `179.7 vs -180.0` → 0.3°.
**실물 검증은 서보 교체 후에 해야 한다.**

**아직 없는 것**: 부하(`Present_Load`) 감시, 이동 전 `wrist_roll` 안전 자세 확인.

✎ 부하 0을 "안 닿음"의 근거로 쓰면 안 된다(토크가 없으면 눌려도 0).

## 2. 완료된 것

### 팔

- **`wrist_roll` 오프셋 -180 등록** (`mapping.json`, 커밋 `7d143bc`)
  서보 중립이 캠-아래로 잡혀 있어, URDF가 `roll=0`으로 푼 해를 그대로 쓰면 실물은
  매번 캠을 아래로 돌린다. 오프셋으로 흡수했다. 중립 재기록은 캘리브 파일과 다른
  실측 상수를 흔들고 과거 사고 전례가 있어 피했다.
  부수 효과: 서보 -180은 URDF 한계(-157.2°, +162.8°) 밖이라 오프셋 없이는 IK가
  "해 없음"을 낸다.

- **`wrist_roll` 최단 경로 래핑** (`arm_gui.py`, 커밋 `68f0656`)
  ±180은 같은 자세인데 서보는 선형 위치 제어라, 0.26° 차이를 359.74° **역회전**으로
  수행한다. 실측: 179.74° → 목표 -180.0°에서 반대로 돌아 92.88°에서 멈췄다.
  전날 카메라가 부서질 뻔한 것도 같은 원인. 등가 각도(±360)를 골라 최단으로 간다.
  검증: 280.53° 역회전 → 79.47° 정방향.

### 뎁스캠

- **컬러 스트림 + depth-to-color registration** (`astra.py`, 커밋 `7af2a97`)
  깊이와 같은 프레임에서 컬러를 꺼내 캐시한다. registration이 켜져야 "컬러에서 찾은
  픽셀의 깊이"가 성립한다. 실측 ON, 640×480.

- **뎁스캠 전용 빨강 HSV** (`panel_server.py`)
  손목캠 값(`S≥150, V≥100, H 174~179`)을 그대로 쓰면 이 카메라에서는 검출 0이다.
  같은 장면 실측: 물체 `H 168~175 · S 중앙 211 · V 중앙 87`, 사람 팔 `H 5~6 · S 117 · V 74`.
  → `V` 하한 100이 물체를 통째로 잘랐고, `H` 상단 구간이 절반을 놓쳤다.
  `S≥140`이면 살색(사람 팔)이 전부 빠진다. 현재 값:
  `[((0,140,55),(10,255,255)), ((166,140,55),(179,255,255))]`

- **깊이 창 확장 탐색** (`panel_server.py`, 커밋 `75e6e05`)
  구조광 방식이라 물체 주변에 그림자가 생기고 작은 큐브는 통째로 들어간다. 고정
  11×11 창에서는 유효 화소 0 → `cam_xyz=None`. `r = 5 → 9 → 14 → 20`으로 넓혀
  유효 화소 8개 이상을 찾는다. 실측: r=9에서 16~29개, z=566mm 안정.

- **Astra 정리 경로 셋** (커밋 `bb27d06`, `7b505aa`)
  ① 초기화 실패가 usbfs 핸들을 남겨 **자기가 연 핸들 때문에 다음 시도가 실패**했다.
  ② daemon 스레드라 종료 시 `close()`가 안 불렸다.
  ③ SIGTERM이 `finally`를 건너뛰었다.
  ④ `shutdown()`이 읽는 스레드가 아직 SDK 안에 있는데 메인에서 `close()`를 불렀다.
     → 플래그 세우고 `join()`으로 **스레드가 스스로 닫고 나올 때까지 기다린 뒤** 닫는다.
  검증: 포트 사이클 없이 재시작 3회 연속 성공, fps 11.7.

- **udev 규칙으로 오디오 인터페이스 차단** (`tools/99-orbbec-noaudio.rules`, 커밋 `5ec375d`)
  Astra는 인터페이스 3개(Vendor Specific 1 + Audio 2)를 노출한다. 커널
  `snd-usb-audio`가 Audio 둘을 claim하면 `libusb_set_configuration`이 `EBUSY(-6)`로
  떨어지고, SDK는 그것을 `Failed to send a USB control request!`로 보고한다.
  공식 규칙은 권한만 다루고 이 문제를 처리하지 않는다.
  **이미 `/etc/udev/rules.d/`에 설치돼 있다.**

- **`tools/usb_port_cycle.sh`** — 포트 VBUS만 껐다 켠다. `/usr/local/sbin/`에 설치돼
  있고 `/etc/sudoers.d/astra-usb`로 무암호 sudo가 허용돼 있다. 원격 작업 중 케이블을
  뽑을 사람이 없을 때 쓴다.

## 3. 해결됨: 뎁스캠 웹 표시 (커밋 `2ef74b7`)

**원인은 스트림 코드가 아니라 SDK 교착이었다.**

Legacy Astra SDK(18.04 바이너리)는 같은 USB2 버스의 UVC 캠이 열리는 순간처럼
대역폭이 출렁일 때 `astra_update()` 안에서 **영구 교착**한다. 교착한 스레드는 같은
프로세스에서 복구할 방법이 없고(파이썬 재연결 루프조차 돌지 않는다), 서버 전체
재시작은 연결 경로가 토크를 풀어 팔을 떨어뜨린다.

**왜 "브라우저에서만 멈춤"으로 보였나** — 교착 후에도 HTTP 핸들러는 살아 있어
캐시된 마지막 JPEG를 계속 보낸다. `/blob`의 stats도 옛 값을 반환한다. 그리고
`/depth`만 단독으로 읽으면 정상으로 보이는데, 그때는 `/cam`이 안 열려 교착이
없기 때문이다. **`/cam`은 되고 `/depth`만 안 되는 대조**가 여기서 나왔다.

`depth_daemon.py`가 캡처를 독립 프로세스로 돌린다:

```
GET /all    → {seq, beat_age, stats, blob, depth_jpeg, rgb_jpeg}   (JPEG 는 base64)
GET /health → {seq, beat_age}
```

`seq`는 새 깊이 프레임마다 증가하고, `beat_age`는 캡처 루프가 마지막으로 한 바퀴 돈
뒤 지난 시간이다. 프레임이 없어도 루프가 살아 있으면 작게 유지되므로, **이 값이 큰
것은 "SDK 안에서 멈춤"만을 뜻한다** — 교착을 정확히 판정하는 계기다.
`panel_server`의 감독 스레드가 하트비트가 끊기면 데몬만 갈아끼운다.

검증: 실제 브라우저에서 6초 6샘플 — 손목캠 6/6, 깊이 6/6 갱신(종전 깊이 1/6).

**진단이 오래 걸린 이유** — `/cam`은 되고 `/depth`만 안 되는데 `/depth` 단독 읽기는
정상이라는 두 사실을 합치면 "**동시에 열 때** 깨진다"가 나왔어야 했다. 그러지 못하고
스트림 형식·`Content-Length`·boundary 충돌 쪽을 오래 팠다. 그 과정에서 넣은
"프레임이 바뀔 때만 전송"·`Content-Length`·`MAX_STREAMS=4`는 전부 증상을 악화시켜
되돌렸다(각각 좀비 스트림 누적, 첫 파트만 읽힘, 새 탭 503).

## 4. 미해결 ②: 정합(hand-eye)

**목표**: `p_rob = R · p_cam + t`. 죠에 물린 빨간 물체로 대응쌍을 모아 Kabsch(SVD)로 푼다.
물체가 죠에서 차지하는 상대 위치는 상수라 `t`에 흡수되므로, 결과는 곧
"카메라가 본 물체 → 그것을 물 TCP 목표"가 되어 죠-물체 오프셋을 따로 잴 필요가 없다.

**세 번 실패했고 원인은 전부 "도달 판정"이었다** (커밋 `ce1e4d0`에 수정 반영):

1. **IK 목표를 로봇 좌표로 썼다.** `fk_pan`은 명령이지 도달 위치가 아니다. 속도 제한이
   걸린 채 큰 이동을 주면 보간 3초가 지나도 팔이 계속 가고 있어, 고정 4.4초 뒤
   측정하면 **직전 위치를 그 지점의 값으로 기록**한다.
   실측: 13점 중 9점의 카메라 좌표가 3mm 안에 뭉쳐 RMS 52.2mm, 최소 특이값 0.003(평면 퇴화).
   → 실제 관절값을 읽어 FK로 로봇 좌표를 구하도록 수정.

2. **"관절 변화가 멈추면 도착"으로 판정했다.** 명령 직후엔 아직 출발 전이라 변화가 0이고,
   그것을 "이미 도착"으로 읽어 13점 전부 같은 자리에서 측정했다.
   → 변화량이 아니라 **목표 관절각과의 거리**로 판정하도록 수정.

3. **각도 래핑을 빠뜨렸다.** `wrist_roll` 목표 -180과 실제 +180은 같은 자세인데 278°
   차이로 읽혀 13점 전부 건너뛰었다.
   → `(a-b+180)%360-180`으로 정규화. **이 수정 직후 사고가 나서 검증되지 않았다.**

### 다음 세션이 정합을 재개할 때

서보 교체·복구가 끝나고 안전장치가 붙은 뒤:

1. 빨간 물체를 죠에 물린다. **물렸는지 반드시 확인할 것** — `shoulder_pan`을 ±6°
   움직여 `/blob`의 `cam_xyz`가 따라 움직이면 물린 것이고, 제자리면 떨어진 것이다.
   (재시작으로 토크가 풀리면 떨어지므로 매번 확인)
2. `python3 ~/so101_tools/handeye.py` — 13개 지점을 자동으로 돈다.
3. 결과는 `~/so101_tools/handeye.json`. **RMS 잔차와 점 분포 특이값을 반드시 볼 것.**
   최소 특이값이 0.02 미만이면 점이 한 평면에 몰린 것이라 회전이 안 정해진다.
4. 팔이 움직이는 동안 자리를 뜨지 말 것. 이번 사고가 그래서 났다.

**지점 좌표**는 실제 IK 도달성을 계산해 다시 잡았다(13점 전부 해 존재 확인).
`z=+0.04` 이상은 리치 밖이고 `z=+0.02`는 `x≤0.22`에서만 풀린다. 아래층은 책상면
(`floor_z=-0.1037`)에서 5cm 여유를 둔 `-0.05`.

## 6. 반복해서 발목을 잡은 것들

- **`systemd-run --user --scope`로 띄운 프로세스는 `kill`로 안 죽는다.** `pgrep -f`가
  잡는 건 래퍼 bash다. 죽인 줄 알았던 서버가 한 시간 넘게 살아 카메라를 물고 있었다.
  `systemctl --user list-units --type=scope | grep <명령>` → `systemctl --user stop <scope>`,
  포트가 비었는지로 교차 확인할 것.

- **USB 리셋 ioctl(`USBDEVFS_RESET`)을 원인 좁히기 전에 걸지 말 것.** 장치가 열거조차
  못 하는 상태(`error -71`)로 굳어, 드라이버 unbind/bind · authorized 토글 · 포트 VBUS
  차단 40초 · xhci 컨트롤러 전체 리셋 · 커널 파라미터 어느 것으로도 복구되지 않았다.
  결국 케이블 재연결로 풀렸다.

- **정적 장면에서는 깊이 프레임이 바이트 단위로 동일하다.** mm 양자화 때문이다.
  카메라가 11fps로 멀쩡히 돌아도 화면은 정지와 구분되지 않는다. 이 착시로 멀쩡한
  세션을 여러 차례 재기동했다. → 깊이 화면 좌상단에 시각·fps를 그려 두었다.

- **`/tmp` 백업으로 롤백하지 말 것.** 임시 실험 전에 `cp panel_server.py /tmp/`로
  받아 둔 백업이 오래된 버전이었고, 그걸 되돌리면서 깊이 창 확장·shutdown join·
  fps 오버레이가 통째로 유실된 채 커밋됐다(`ce1e4d0`). git에서 복구했다.

## 7. 파일 위치

**실행 경로는 `~/so101_tools/`다.** 리포의 `projects/so101-arm/tools/`는 **사본**이고,
`panel_server.py`가 `sys.path`에 `~/so101_tools`를 넣어 그쪽을 import한다.
둘이 어긋날 수 있으니 수정 후 반드시 복사할 것.

| 파일 | 역할 |
|---|---|
| `panel_server.py` (리포) | HTTP 서버. `/state` `/cmd` `/cam` `/depth` `/rgb` `/blob`. 깊이 데몬 감독 |
| `depth_daemon.py` (리포) | 깊이 캡처 전용 프로세스 (포트 8766). SDK 교착을 격리한다 |
| `~/so101_tools/arm_gui.py` | 시리얼 워커. 토크·조그·IK 이동·정지 |
| `~/so101_tools/arm_lib.py` | 매핑·운동학 로드, 관절각 ↔ 서보각 변환 |
| `~/so101_tools/astra.py` | Astra ctypes 바인딩 (깊이·컬러·registration) |
| `~/so101_tools/handeye.py` | 정합 스크립트 (미검증) |
| `~/so101_tools/mapping.json` | 부호·오프셋·홈 자세 |
| `~/so101_tools/servo_gain.json` | 실측 상수 (`floor_z_m`, `cam_up_roll_deg` 등) |

**서버 기동**:

```
systemd-run --user --scope -q -p MemoryMax=1G bash -c \
  'export PYTHONPATH=; export LD_LIBRARY_PATH=$HOME/AstraSDK/lib:$LD_LIBRARY_PATH; \
   cd ~/robot-dashboard/projects/so101-arm && exec ~/miniforge3/envs/lerobot/bin/python -u panel_server.py'
```

`panel_server`가 `depth_daemon.py`를 자동으로 띄우고 감독한다(따로 실행할 필요 없음).

기동 후 `{"op":"connect"}` → 속도 낮추고 → `{"op":"torque","on":true}` → 즉시 `{"op":"stop"}`.
(연결 시 `disable_torque()`가 불려 팔이 처지므로 미리 낮은 자세로 둘 것.
토크를 켤 때 이전 목표로 튀는 것을 `stop`으로 막는다.)
